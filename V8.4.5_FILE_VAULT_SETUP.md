# Workday Journey V8.4.5 - Project File Vault Setup

## Do this once in Supabase
1. Open your existing Workday Journey Supabase project.
2. Go to **SQL Editor** -> **New query**.
3. Paste/run `SUPABASE_FILE_VAULT_SETUP.sql`.
4. After it succeeds, check **Storage**. A private bucket named `project-files` should exist.
5. Check **Table Editor**. A table named `project_file_versions` should exist.
6. Keep the existing `supabase-config.js`; no Service Role key is needed or allowed in the frontend.

## Limits used by V8.4.5
- 20 MB maximum per upload (hard limit also set on the bucket).
- 8 logical files per Project.
- 100 MB soft quota per User in the app, counting every saved version.
- Allowed app extensions: ZIP, PDF, DOC/DOCX, XLS/XLSX, PPT/PPTX, PNG/JPG/JPEG/GIF/WEBP, TXT/MD/CSV/JSON.

## Privacy
The bucket is private. RLS/Storage policies allow an authenticated user to read, upload, rename metadata, and delete only objects whose first path folder equals their own `auth.uid()`.

## Test
1. Sign in to Workday Journey Cloud.
2. Open **Projects**.
3. Save/open a Project and press **Project Files**.
4. Upload a small PDF or ZIP.
5. Refresh and download it again.
6. Sign in as another user: that account should not see the first user's files.
