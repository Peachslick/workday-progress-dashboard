# Workday Journey V8.6.0.3 - Legacy Recovery (Owner Approval)

## Scope / safety

- Base version: V8.6.0.2 (the deployed release). **Do not deploy V8.6.1.0 for this recovery.**
- Existing Guest/Cloud wallet and Bank engine remains unchanged.
- Opening the application on the **same browser + same exact site origin** stages a copy of old Bank backup and Exchange trade history for review. Users do not need Developer Tools.
- No amount, stock, or Coin is credited when the user logs in. All restoration must be approved by the Owner.
- Evidence from browser storage is not trustworthy, even when it has timestamps. Verify against account transaction records or other evidence before accepting any recovery claim.
- Never run scripts that clear browser data, uninstall the PWA, or change the site's URL during the recovery window.
- The approved Exchange trade snapshot is saved on the server. The client rehydrates a **completely empty** local trade list on that account; it intentionally does not overwrite non-empty local lists.
- Work Exchange trading itself is still local in this version and will require a separate server-authoritative update.

## Install in this order

1. Back up your existing code, SQL schema (database backup), and recoverable browser data where possible. Prefer a staging environment to test.
2. Confirm SQL from V8.5.0.1, V8.6.0 and V8.6.0.1 Bank is installed.
3. In SQL Editor, run `SUPABASE_LEGACY_RECOVERY_V8.6.0.3.sql` **one time** (idempotent DDL/functions). It creates two restricted tables and five RPC endpoints.
4. Copy only these website files from the ZIP to your current website root: `index.html`, `service-worker.js`, `v8.js`, `v850.js`, `v8501.js`, `v851.js`, `v852.js`, `v853.js`, `v854.js`, `v855.js`, `v8602.js`, `v8603.js`, `v8603.css`.
5. Deploy (e.g. Git push) and reload using Ctrl+Shift+R. Do not delete the original `localStorage` or reset app data.
6. Use an Owner account to open `#/developer`, scroll down to **LEGACY RECOVERY**, and click Refresh.
7. Ask affected users to open the **same exact URL and browser/device** they previously used, then sign in to their existing account. The app submits a pending *recovery evidence* case; no user intervention is required.
8. Review one case: claimed Bank amount, old transactions, trade symbols/quantities, potential duplicates, and the person's account. Enter the amount *you independently verified* (integer Coins). Select `wallet_transfer` for preserving total Coins, or `verified_compensation` only when you have independent proof the wallet was already debited and document the reason.
9. Check `Restore verified stock history` only if trades are plausible and belong to this user. Provide an audit reason (at least 10 characters) and approve/reject. One reviewed case cannot be approved twice. One Bank restoration and one Exchange snapshot per account are allowed.
10. Ask the affected user to reload once, then check Bank savings, wallet, and Exchange Portfolio on the same browser and another device. Check the transaction history. Try with a test user before broad rollout.

## Important limitations

- The automatic scanner is limited to this origin's existing `localStorage`. It cannot read storage from another domain, port, profile, cleared site, or browser.
- Bank evidence comes from `wdj-v8601-guest-bank-backup` and might be an **unverified Guest snapshot**. If missing, do not synthesize a balance.
- Trade evidence comes from `wp-v84-exchange-trades` and is also **unverified**. Old non-empty trades remain untouched on the same browser; the approved snapshot is retained server-side and restored automatically only to an empty local history.
- If two people used the same browser in the past, evidence may be mixed. Do not approve without independently checking ownership.
- `wallet_transfer` moves Coins from wallet to savings atomically; it will fail if wallet is insufficient.
- `verified_compensation` **increases total saved Coins**. This is a privileged, audited exception: use only when records prove restoration is warranted, or choose amount 0 and investigate further.
- Previous trades or balance may already have been restored via another route. Cross-check cloud wallet/Bank transactions and avoid approving duplicate claims.
- No anonymous endpoint can approve funds. Owner permission is checked by SQL, not by hiding UI controls.

## SQL checks for the Owner (read-only)

```sql
select status, count(*) from public.wdj_legacy_recovery_requests group by status;
select user_id,status,created_at,reviewed_at,approved_bank_amount,bank_mode,approved_stocks
from public.wdj_legacy_recovery_requests order by created_at desc limit 50;
select user_id,savings from public.work_bank_accounts order by updated_at desc limit 30;
select user_id,request_id,approved_at from public.wdj_legacy_exchange_recovered;
```

## Rollback

- Revert the changed website files to V8.6.0.2. Leave the recovery tables in place to preserve evidence and the audit trail.
- Do **not** delete recovered Bank transaction rows or edit Coin balances manually. Reversals require independently reviewed compensating transactions.
