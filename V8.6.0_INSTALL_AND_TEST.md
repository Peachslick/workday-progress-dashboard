# Workday Journey V8.6.0 - Guest to Cloud Security Fix

## Deployment (IMPORTANT: SQL FIRST)

1. Back up your Supabase data. Confirm V8.5.0.1 SQL has already been applied.
2. In Supabase SQL Editor, run **SUPABASE_SECURITY_V8.6.0_GUEST_CLOUD_FIX.sql** **once** (safe to re-run).
3. Deploy the 12 changed web files from this patch ZIP to your V8.5.5 project root. Do not replace other files.
4. Reload the website (Ctrl+Shift+R), or Clear App Cache / Reload Latest Version in the PWA.
5. Verify the new version label is V8.6.0. Confirm `get_my_economy()` succeeds for a signed-in user.

### Why SQL must be applied first

An old site, cached script, custom Console call, or direct PostgREST request
can bypass frontend checks. The SQL disables the vulnerable RPC itself.
**Deploying JavaScript without running the SQL DOES NOT close the exploit.**

### Expected behavior

- Guest may play with local Coins and rewards; local DevTools can still modify them.
- On signup/login, the Cloud balance and inventory come from Supabase. Guest
  Coin totals and owned rewards are not imported.
- After signing out, the Guest local ledger/owned items are restored if they
  were saved before an interactive sign-in on this device. The Guest snapshot
  is device-only and does not sync.
- Existing users who already imported before V8.6.0 keep their balances/items.
- Existing users who never imported cannot self-import after this update.
  Their server balance may be 0; arrange OWNER-verified manual restoration if needed.
- Guest entries may still be visible in local Coin History while signed in due
  to old UI ledger architecture. This patch prevents server credit, not all
  locally fabricated history. A server-only history is planned for later.

### Security test checklist

1. In Guest mode create 9,999 test Coins through normal local testing.
2. Register a fresh Supabase account. After signin/reload, Cloud balance should
   match `public.work_coin_accounts` (0 if no server award was given).
3. In Supabase SQL Editor run the read-only audit query at the end of the SQL
   file; do not see a new `migration:v8501` entry for this new account.
4. Directly try the old `import_legacy_economy` RPC *as that authenticated user*
   with a non-production test account. It must fail with permission denied or
   LEGACY_IMPORT_DISABLED_V860. Verify the server balance did not change.
5. Sign out; local Guest Coins should return on that browser. Sign in to a
   previously migrated account and verify the existing genuine balance remains.
6. Redeem a valid Reward Code and buy an Item from the Shop to confirm normal
   authenticated RPC operations still work.

### Important remaining limitations

- The legacy imported balances already on the server are not automatically
  proven legitimate or revoked. The owner must audit them separately.
- Missions, Chest, Work Bank, and Work Exchange are still partially client-side.
- Rewards can sometimes be displayed inconsistently in the old Coin History UI;
  only server records are authoritative while authenticated.
- Protection depends on correct Supabase grants/RLS; manually test the live
  project after SQL deployment. Do not rely on blocking F12.
